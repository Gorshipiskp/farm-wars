# Context

Нужен минимальный клиентский интерфейс, который позволяет создать/войти в матч, видеть состояние фермы и отправлять
базовые действия. Без этого игра не является играбельной.

# Goal

Реализовать базовый `pygame` клиент с экранами lobby/match и отправкой ключевых действий на сервер.

# Scope

In scope:

- экран создания/входа в матч,
- экран матча с сеткой и базовым HUD,
- отображение состояния от сервера,
- отправка минимум 3 action-типов.

Out of scope:

- финальный арт/UI полировка,
- сложные анимации,
- расширенные UX-механики.

# Functional Requirements

- Реализовать lobby UI:
    - create match,
    - join by code.
- Реализовать match UI:
    - сетка грядок/загона,
    - отображение валюты и цели матча,
    - список очередей заводов.
- Реализовать отправку действий:
    - посадка/действие на клетке,
    - полив,
    - старт рецепта на заводе.
- Реализовать прием и применение серверных state sync сообщений.

# Non-Functional Requirements

- Клиент должен запускаться локально на Windows без сложной настройки.
- UI должен оставаться отзывчивым при сетевых обновлениях.
- Ошибки сети должны отображаться понятно (без краша клиента).

# Data Contracts / API Contracts

- Клиент использует только контрактные сообщения из `GAME_CONTRACTS_V1`.
- Все исходящие сообщения должны включать `match_id` и `player_id`.
- Входящие `StateSyncEvent` считаются единственным источником серверного состояния.

# Implementation Plan

1. Сделать структуру экранов `lobby` и `match`.
2. Добавить сетевой клиентский адаптер.
3. Связать input игрока с `ClientActionEnvelope`.
4. Реализовать рендер ключевых элементов мира.
5. Добавить обработку ошибок и reconnect-fallback поведение.

# Checkpoints

1. **Lobby Flow Approved**
    - Артефакт: рабочие действия create/join.
    - Проверка: игрок входит в матч по коду.
2. **Match Render Approved**
    - Артефакт: экран матча.
    - Проверка: состояние мира видимо и обновляется по входящим sync.
3. **Action Send Approved**
    - Артефакт: отправка минимум 3 action-типов.
    - Проверка: действия доходят до сервера и отражаются в мире.
4. **UX Stability Approved**
    - Артефакт: обработка сетевых ошибок.
    - Проверка: при ошибке сеть/сервер клиент не падает.

# Acceptance Criteria

- Игрок может создать или подключиться к матчу.
- Игрок видит мир и его изменения.
- Игрок может выполнять базовые действия из UI.
- Клиент и сервер работают совместно в одном вертикальном сценарии.

# Test Plan

- Ручной сценарий create -> join -> start match (localhost).
- Тот же сценарий в LAN: гость вводит IP хоста, Connect, Join.
- Ручной сценарий действий на клетках и запуска рецепта.
- Проверка обновления UI при серверных тиках.
- Негативный тест на временную недоступность сервера.
