# Context

Проект стартует с нуля. Команда работает параллельно на Python и C++, поэтому без жестких контрактов возрастает риск
несовместимых реализаций и блокировок.

# Goal

Зафиксировать `v1` архитектурные границы модулей и межмодульные контракты так, чтобы `NIKITA` и `SANYA` могли
разрабатывать независимо.

# Scope

In scope:

- структура модулей `client/server/shared/db/engine_cpp`,
- контракт тика `TickInput -> TickResult`,
- контракт сетевых команд клиента,
- версия контрактов и правила обратной совместимости.

Out of scope:

- реализация игрового UI,
- реализация боевой сетевой логики,
- полная реализация C++ симуляции.

# Functional Requirements

- Создать документ архитектуры `docs/contracts/ARCHITECTURE_V1.md`.
- Создать документ контрактов `docs/contracts/GAME_CONTRACTS_V1.md`.
- Описать владельца каждого модуля и границы ответственности.
- Зафиксировать форматы:
    - `WorldState`,
    - `PlayerAction`,
    - `TickInput`,
    - `TickResult`,
    - `ServerEvent`.
- Определить правило версионирования контрактов (`contract_version`).

# Non-Functional Requirements

- Все контракты должны быть читаемы новичком за 15-20 минут.
- Термины должны совпадать между документами.
- Изменения в контрактах должны быть детерминированно отслеживаемы через версию.

# Data Contracts / API Contracts

- `TickInput`: `contract_version`, `tick_id`, `world_state`, `actions`.
- `TickResult`: `contract_version`, `tick_id`, `next_world_state`, `events`.
- `PlayerAction`: `player_id`, `action_type`, `payload`, `client_ts`.
- `ServerEvent`: `event_type`, `payload`, `server_tick`.

# Implementation Plan

1. Зафиксировать список модулей и владельцев.
2. Описать жизненный цикл одного тика.
3. Описать сетевые входные команды и серверные события.
4. Описать формат ошибок контракта и политику совместимости.
5. Провести ревью с `NIKITA` и `SANYA`.

# Checkpoints

1. **Module Boundaries Approved**
    - Артефакт: раздел границ модулей в `ARCHITECTURE_V1.md`.
    - Проверка: у каждого модуля есть владелец и зона ответственности.
2. **Tick Contract Approved**
    - Артефакт: `TickInput/TickResult` в `GAME_CONTRACTS_V1.md`.
    - Проверка: Python и C++ могут реализовать интерфейс независимо.
3. **Network Contract Approved**
    - Артефакт: список `PlayerAction` и `ServerEvent`.
    - Проверка: серверная и клиентская команды не имеют неоднозначных полей.
4. **Team Sign-Off**
    - Артефакт: зафиксированная версия `v1`.
    - Проверка: оба разработчика подтверждают, что могут начать свои ТЗ без ожидания.

# Acceptance Criteria

- Документы контрактов `v1` созданы и согласованы.
- Есть однозначные структуры для тика и сетевых сообщений.
- Есть правила версионирования и изменений.
- Следующие ТЗ (`db`, `engine_cpp`, `server`, `client`) могут ссылаться на этот контракт без уточнений.

# Test Plan

- Ручная проверка полноты полей по чеклисту.
- Ревью на предмет противоречий между архитектурой и контрактами.
- Подтверждение от `NIKITA` и `SANYA`, что документы покрывают их потребности для старта.
