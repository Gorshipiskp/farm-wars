# Context

Игра должна загружать контент декларативно из SQLite. Без базовой нормализованной схемы и минимальных seed-данных
невозможно стабильно запускать одиночный и мультиплеерный сценарии.

# Goal

Создать минимальную нормализованную SQLite-схему с FK и стартовые seed-данные для вертикального среза матча.

# Scope

In scope:

- SQL схема таблиц сущностей и связей,
- FK и базовые ограничения,
- минимальный `seed_minimal.sql`,
- загрузка данных сервером при старте.

Out of scope:

- сложные миграции,
- баланс большого количества контента,
- внешняя БД (PostgreSQL и др.).

# Functional Requirements

- Создать `db/schema.sql` с таблицами:
    - `products`,
    - `plants`,
    - `animals`,
    - `recipes`,
    - `recipe_ingredients`,
    - `buildings`,
    - `random_events`,
    - `sabotages`,
    - `countermeasures`.
- Добавить внешние ключи и базовые `NOT NULL/CHECK`.
- Создать `db/seed_minimal.sql` для минимум:
    - 3 растения,
    - 1 животное,
    - 2 рецепта,
    - 1 целевой продукт для победы.
- Реализовать загрузчик на стороне Python server.

# Non-Functional Requirements

- Схема должна быть читаемой и расширяемой.
- Seed-данные должны быть детерминированными.
- Развертывание локально должно занимать не более 1 команды.

# Data Contracts / API Contracts

- `Recipe` содержит `production_time_sec`, `price_override`.
- При `price_override IS NULL` используется формула по умолчанию.
- Все ссылки из `recipe_ingredients` на `recipes/products` должны иметь FK.

# Implementation Plan

1. Спроектировать таблицы и связи.
2. Реализовать `schema.sql`.
3. Подготовить `seed_minimal.sql`.
4. Реализовать Python-инициализацию БД при старте.
5. Проверить чтение рецептов и продуктов сервером.

# Checkpoints

1. **Schema Approved**
    - Артефакт: `db/schema.sql`.
    - Проверка: схема создается без ошибок и содержит FK.
2. **Seed Approved**
    - Артефакт: `db/seed_minimal.sql`.
    - Проверка: после seed есть необходимый минимальный контент.
3. **Server Load Approved**
    - Артефакт: модуль загрузки данных.
    - Проверка: сервер при старте читает рецепты и продукты из SQLite.
4. **Formula Fallback Approved**
    - Артефакт: функция расчета цены при `NULL`.
    - Проверка: для рецепта без `price_override` применяется стандартная формула.

# Acceptance Criteria

- Есть рабочие `schema.sql` и `seed_minimal.sql`.
- Сервер запускается и читает контент из БД.
- Контент достаточен для первого играбельного среза.
- Контракт рецептов совместим с архитектурным `v1`.

# Test Plan

- Локально поднять SQLite из `schema.sql`.
- Применить `seed_minimal.sql` и проверить количество записей.
- Запустить сервер и проверить логи загрузки.
- Проверить два кейса цены: `price_override` задан и `NULL`.
