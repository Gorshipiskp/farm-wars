# Context

`engine_cpp/002.SANYA.PLACE_ON_TILE` реализовал посадку в `simulate_tick`.
Движок ожидает обогащённый payload: `initial_health`, `initial_water_level`.
Клиент отправляет только `{tile_id, plant_id}`.

Сервер сейчас передаёт actions в движок без изменений — посадка в матче не работает.

# Goal

Обогатить `PLACE_ON_TILE` на сервере перед вызовом `simulate_tick` и выдать стартовые семена при создании мира.

# Scope

In scope:

- обогащение payload из `GameContentCatalog` (`db/loader.py`),
- стартовый инвентарь семян при `start_match` (из fixture-шаблона),
- тест интеграции server → engine stub,
- обновление `GAME_CONTRACTS_V1` (`PLANT_PLACED`).

Out of scope:

- магазин семян в UI клиента,
- посадка животных,
- изменения C++ движка (`SANYA`).

# Functional Requirements

1. Перед `simulate_tick` для каждого `PLACE_ON_TILE`:
    - `initial_health` = `100`,
    - `initial_water_level` = `plants[plant_id].initial_water_level` из каталога.
2. Если `plant_id` не найден в каталоге — не вызывать движок для этого action; вернуть `CONTRACT_ERROR` в sync.
3. При `create_initial_world` копировать стартовый `inventory` из `fixtures/world_state/minimal_world.json` на каждого игрока.
4. Клиентский payload не менять.

# Data Contracts / API Contracts

См. `docs/specs/engine_cpp/002.SANYA.PLACE_ON_TILE.md` (обогащённый payload, событие `PLANT_PLACED`).

# Implementation Plan

1. `server/action_enricher.py` — `enrich_actions_for_tick(actions, catalog)`.
2. Вызов из `Match.process_tick` перед `simulate_tick`.
3. `world_factory.py` — стартовый инвентарь из fixture.
4. Тест в `tools/test_server_flow.py`.
5. Обновить `GAME_CONTRACTS_V1.md`.

# Acceptance Criteria

- Клиент шлёт `{tile_id, plant_id}` — матч обрабатывает посадку.
- В sync появляется `PLANT_PLACED`, инвентарь уменьшается.
- Неизвестный `plant_id` даёт понятную ошибку без падения сервера.
