# Что сделал SANYA (engine_cpp/004)

## Новые механики случайных событий

Вместо мгновенных эффектов — изменение правил симуляции:

| Событие | Старая механика | Новая механика |
|---|---|---|
| `DROUGHT` (засуха) | water_level −20 | `water_decay_per_tick` × 1.5 для всех PLANT-грядок |
| `FLOOD` → `RAIN` (дождь) | water_level +30 | `water_decay_per_tick` становится **отрицательным**: −max(1, decay × 0.2). Вода **растет** каждый тик |
| `EARTHQUAKE` (землетрясение) | health −30 растениям | `remaining_time_sec` × 1.5 у всех активных заводов |
| `EPIDEMIC` (эпидемия) | health −40 животным | Заглушка (животные не реализованы) |

### Как это работает
- События меняют **свойства мира** (decay, remaining_time), а не мгновенные значения
- Пассивная фаза подхватывает изменения автоматически
- Вода капуется на 100 (дождь не переполняет)
- Движок принимает `event_type: "RAIN"` (и `"FLOOD"` для обратной совместимости)

5 тестов (10a–10e): засуха, дождь, кап воды, землетрясение, неизвестный тип.

# Что нужно NIKITA

## 1. Переименовать FLOOD → RAIN
В файлах сервера и БД:
- `db/seed_minimal.sql`: `effect_type` для `flood` → `rain`, `display_name` → `"Дождь"`
- `db/schema.sql`: CHECK constraint (добавить `'RAIN'`)
- Все упоминания "FLOOD" в серверном коде заменить на "RAIN"

## 2. Серверный триггер событий (основное)
Раз в N тиков (например, каждые 30) с вероятностью 20%:
1. Выбрать случайное событие из `random_events` в БД
2. Отправить в движок `APPLY_EVENT` с `payload: {event_type: "RAIN"}`
3. События обрабатываются в рамках того же тика

Движок полностью готов принимать `APPLY_EVENT` с любым из 4 типов.

## 3. EPIDEMIC (после реализации животных)
Когда появятся животные — обновить обработчик эпидемии в движке (уменьшение скорости роста).
