# Context

В мультиплеере у каждого игрока своя ферма (`owner_player_id` на клетках). Действия `PLACE_ON_TILE`, `HARVEST_PLANT`, `FEED_ANIMAL` уже проверяли владельца в C++/stub; **`WATER_PLANT`** до исправления позволял полить чужую грядку (уязвимость и ломает баланс PvP).

# Goal

Все действия игрока на **клетке** в движке должны требовать `tile.owner_player_id == action.player_id`, если иное не оговорено (саботаж — server-only на чужих клетках).

# Scope

**In scope:**

- `WATER_PLANT` в `engine_cpp/src/simulate_tick.cpp` и `engine_core_stub/stub.py`.
- Событие при отказе: `CONTRACT_ERROR` (`INVALID_TYPE`, сообщение про владельца).
- Автотест в `tools/test_multiplayer.py`.

**Out of scope (backlog):**

- `START_RECIPE` на чужом `factory_id` — сейчас не проверяется в C++; клиент не должен слать чужой id.
- Рефакторинг `find_tile()` (возврат ссылки вместо копии `py::dict`) — отдельная задача `SANYA`.

# Functional Requirements

1. `WATER_PLANT` с `payload.tile_id`, где `owner_player_id != player_id` → **нет** `PLANT_WATERED`, есть `CONTRACT_ERROR`.
2. Свой полив → `PLANT_WATERED`, `water_level` обновляется.
3. Поведение stub и C++ согласовано (smoke / MP test).
