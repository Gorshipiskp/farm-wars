# Context

Для мультиплеера нужен серверный авторитетный контур: создание комнаты, вход по коду и псевдо-реалтайм тик-обновление.
Без него нельзя сыграть командный матч.

# Goal

Реализовать базовый сервер матча с `join by code`, обработкой actions от клиентов и рассылкой серверного состояния по
тикам.

# Scope

In scope:

- создание матча и выдача join-кода,
- подключение 2+ игроков,
- прием client actions,
- запуск тик-цикла,
- рассылка `ServerEvent/WorldState`.

Out of scope:

- продвинутый матчмейкинг,
- ранговая система,
- авторизация пользователей.

# Functional Requirements

- Реализовать endpoint/handler создания комнаты.
- Реализовать endpoint/handler входа в комнату по коду.
- Реализовать очередь входящих действий от клиентов.
- Реализовать серверный loop фиксированного тика.
- Интегрировать вызов `engine_core` (или его stub до готовности C++).
- Реализовать проверку победного условия по целевому продукту.

# Non-Functional Requirements

- Сервер не должен принимать клиентское "готовое состояние".
- Ошибки входа по коду должны быть обработаны без падения процесса.
- Один матч должен стабильно обслуживать минимум 2 игроков в локальной сети/localhost.

# Data Contracts / API Contracts

- `CreateMatchResponse`: `match_id`, `join_code`.
- `JoinMatchRequest`: `join_code`, `player_name`.
- `ClientActionEnvelope`: `match_id`, `player_id`, `action`.
- `StateSyncEvent`: `tick_id`, `world_state`, `events`.

# Implementation Plan

1. Реализовать in-memory реестр матчей.
2. Реализовать create/join flow.
3. Реализовать action queue на матч.
4. Реализовать тик-обработчик и вызов движка/stub.
5. Реализовать победное условие и завершение матча.

# Checkpoints

1. **Join Flow Approved**
    - Артефакт: create/join handlers.
    - Проверка: 2 клиента могут зайти в одну комнату по коду.
2. **Tick Loop Approved**
    - Артефакт: серверный таймер/loop.
    - Проверка: сервер публикует синхронизации состояния по тикам.
3. **Engine Integration Approved**
    - Артефакт: интеграция с `engine_core` или stub.
    - Проверка: action игрока влияет на состояние мира.
4. **Win Condition Approved**
    - Артефакт: завершение матча по целевому продукту.
    - Проверка: сервер корректно объявляет победителя.

# Acceptance Criteria

- Работает создание и вход в матч по коду.
- Есть стабильный серверный тик и обработка действий.
- Состояние мира синхронизируется клиентам.
- Матч корректно завершается при выполнении победного условия.

# Test Plan

- Ручной тест 2 клиентами на localhost.
- Отправка базовых действий и проверка состояния.
- Тест некорректного join-кода.
- Тест завершения матча по достижению цели.
