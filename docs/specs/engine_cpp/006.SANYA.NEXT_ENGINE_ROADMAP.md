# engine_cpp/006 — SANYA: дорожная карта движка

**Статус:** `PLANNED`  
**Владелец:** `SANYA`  
**Зависимости:** контракты `docs/contracts/GAME_CONTRACTS_V1.md`, обогащение на сервере (`NIKITA`)

---

## Контекст

Движок (`engine_cpp` + `engine_core_stub`) закрывает MVP-симуляцию:

- `WATER_PLANT`, `PLACE_ON_TILE`, `HARVEST_PLANT`, `START_RECIPE`
- `FEED_ANIMAL`, пассивное молоко
- `APPLY_EVENT` (случайные события)
- пассивная фаза: вода, рост, смерть растений, тик заводов, очередь рецептов

Сервер и клиент уже шлют обогащённые payload (семена `seed_product_id` / урожай `crop_product_id`).  
Дальше — **качество MP**, **безопасность действий**, **контрмеры**, подготовка к новому контенту без ломки контракта.

## Задачи (приоритет)

### P0 — Must (блокирует честный MP)

#### 006.1 — `player_id` в `CONTRACT_ERROR`

**Проблема:** ошибки движка не содержат `player_id` → все клиенты видят чужие ошибки в sync/тостах.

**Сделать:**

1. В `_make_error_event` / `make_error_event` (stub + C++) добавить в `payload`:
   - `player_id: string` — из текущего `PlayerAction`
2. Обновить `GAME_CONTRACTS_V1.md` (секция `CONTRACT_ERROR`).
3. Тест в `smoke_test.py`: два действия в одном тике, ошибка только у одного игрока, в payload есть `player_id`.

**Критерий приёмки:** `NIKITA` может фильтровать тосты по `payload.player_id` для всех `CONTRACT_ERROR`.

---

#### 006.2 — `START_RECIPE`: владелец завода

**Проблема:** игрок теоретически может отправить `factory_id` соперника (см. backlog в `server/009`).

**Сделать:**

1. Перед стартом рецепта: `factory.owner_player_id == action.player_id`.
2. Иначе: `RECIPE_REJECTED` с `reason: "NOT_OWNER"` (предпочтительнее, чем `CONTRACT_ERROR`).
3. Зеркально в stub; тест в `smoke_test.py` или `test_multiplayer.py`.

**Критерий приёмки:** `tools/test_multiplayer.py` — сценарий «p2 не может печь на p1_bakery_1».

#### 006.4 — `USE_COUNTERMEASURE` в движке

**Зависимость:** `NIKITA` реализует `server/010` (immediate handler + клиент).

**Сделать (после контракта от NIKITA):**

- Обработать `USE_COUNTERMEASURE` (или server-only + эффект через `APPLY_EVENT` — согласовать в TEAM-CP).
- Эффекты из `countermeasures` в БД: снятие дебаффа / иммунитет на N тиков на тайле или игроке.
- События: `COUNTERMEASURE_APPLIED` / `COUNTERMEASURE_FAILED`.

**Файлы:** `simulate_tick.cpp`, `stub.py`, контракты, smoke.

---

#### 006.5 — Жёсткая проверка `RECIPE_FINISHED`

Убедиться, что продукт в инвентарь — **`output_product_id`** из enricher, а не `recipe_id` (замечание TEAM-CP-003).

- Тест: рецепт с `output_product_id != recipe_id` (если появится в seed).
