# Context

Нужна базовая C++ симуляция, вызываемая из Python. Без этого не проверить кросс-языковую архитектуру и не обеспечить
детерминированный тик движка.

# Goal

Собрать базовый C++ модуль `engine_core` с pybind11 и реализовать минимальный deterministic tick API, совместимый с
контрактом `v1`.

# Scope

In scope:

- CMake-проект C++ ядра,
- pybind11 binding и импорт из Python,
- `simulate_tick(input) -> result`,
- минимальная логика изменения состояния (заглушка).

Out of scope:

- полная бизнес-логика всех механик,
- оптимизация производительности,
- сложные C++ подсистемы.

# Functional Requirements

- Создать структуру `engine_cpp/` с CMake-конфигурацией.
- Подключить `pybind11`.
- Экспортировать функцию `simulate_tick`.
- Принимать структуры входа, совместимые с контрактом `TickInput`.
- Возвращать `TickResult` с валидным `next_world_state` и `events`.
- Обработать минимум 2 action-типа:
    - `WATER_PLANT`,
    - `START_RECIPE`.

# Non-Functional Requirements

- Сборка должна выполняться на Windows.
- Вызов из Python должен быть стабилен и повторяем.
- Для одинакового входа результат должен быть одинаковым.

# Data Contracts / API Contracts

- Вход: `TickInput` (`contract_version`, `tick_id`, `world_state`, `actions`).
- Выход: `TickResult` (`contract_version`, `tick_id`, `next_world_state`, `events`).
- Ошибка контракта должна возвращать понятный текст (исключение или error object).

# Implementation Plan

1. Подготовить CMake и структуру исходников.
2. Подключить pybind11 и настроить сборку модуля.
3. Реализовать структуры и адаптер входа.
4. Реализовать `simulate_tick` с минимальной deterministic-логикой.
5. Сделать smoke-скрипт Python с вызовом модуля.

# Checkpoints

1. **Build Chain Approved**
    - Артефакт: CMake + успешная сборка `engine_core`.
    - Проверка: модуль импортируется в Python.
2. **API Contract Approved**
    - Артефакт: `simulate_tick`.
    - Проверка: функция принимает вход по `v1` и возвращает `TickResult`.
3. **Deterministic Behavior Approved**
    - Артефакт: smoke test.
    - Проверка: одинаковый input дает одинаковый output.
4. **Action Handling Approved**
    - Артефакт: обработка двух action-типов.
    - Проверка: в `next_world_state/events` отражаются изменения от команд.

# Acceptance Criteria

- C++ модуль собирается и вызывается из Python.
- Контракт тика соблюден.
- Минимальная логика работает детерминированно.
- Python-команда может интегрировать модуль без ожидания дальнейших задач `SANYA`.

# Test Plan

- Сборка модуля в чистой среде Windows.
- Python smoke test импорта и вызова.
- Проверка повторяемости результата на фиксированных fixture-входах.
- Негативный тест: некорректный контрактный вход.
