# Фаза 1 — Рост растений и вода за тик (приоритет HIGH)

## Смысл для игрока

- Посадил → полил → **ждёшь** (тики) → растение **созрело** → собрал.
- Не полил — вода падает, урожай может **засохнуть**.

## Данные на клетке (`TileState`)

Добавить **опциональные** поля (forward-tolerant контракт v1):

| Поле | Тип | Описание |
|------|-----|----------|
| `growth_elapsed_sec` | number | Сколько «секунд роста» уже прошло (0 после посадки) |
| `growth_time_sec` | number | Порог созревания (копия из каталога, приходит с сервера) |
| `water_decay_per_tick` | number | Сколько снимать воды за 1 тик (с сервера) |

Сервер (`NIKITA`) в `action_enricher` для `PLACE_ON_TILE` добавит в payload (из `plants` в SQLite):

```json
{
  "tile_id": "p1_t3",
  "plant_id": "wheat",
  "initial_health": 100,
  "initial_water_level": 50,
  "growth_time_sec": 120,
  "water_decay_per_tick": 2
}
```

При посадке движок выставляет на tile: `growth_elapsed_sec = 0`, `growth_time_sec`, `water_decay_per_tick` из payload.

## Пассивная фаза (каждый `simulate_tick`, после actions)

Для каждой клетки с `occupant_type == "PLANT"`:

1. `water_level = max(0, water_level - water_decay_per_tick)` (если поля нет — decay = 0).
2. Если `water_level > 0`: `growth_elapsed_sec += 1` (1 тик = 1 сек, как у заводов на сервере).
3. Если `water_level == 0` и `health > 0`: `health -= 10` (константа MVP, вынести в `#define` / константу).
4. Если `health <= 0`: очистить клетку (`EMPTY`), событие `PLANT_DIED` `{tile_id, plant_id, player_id, reason: "DEHYDRATED"}`.

Опционально раз в N тиков — `PLANT_GROWTH_TICK` не обязательно (не спамить events); достаточно состояния в `world_state`.

## Созревание (для фазы 2 harvest)

Растение **можно собирать**, если:

- `growth_elapsed_sec >= growth_time_sec`
- `water_level >= 50` (как сейчас в server harvest MVP)

Константу `50` можно назвать `HARVEST_MIN_WATER` в коде.

## Checkpoint 1 — «Growth Approved»

- [ ] После посадки на tile есть `growth_elapsed_sec`, `growth_time_sec`.
- [ ] 3 тика подряд без полива — вода уменьшается по `water_decay_per_tick`.
- [ ] При нулевой воде health падает, при 0 — `PLANT_DIED`, клетка пустая.
- [ ] С поливом `growth_elapsed_sec` растёт.
- [ ] Stub и C++ дают одинаковый `next_world_state` на фикстурном сценарии.
- [ ] `smoke_test.py`: минимум 2 новых теста.

# Фаза 2 — `HARVEST_PLANT` в движке (приоритет HIGH)

## Смысл

Сейчас сбор делает `server/harvest.py` (immediate). Нужно **то же правило** в `simulate_tick`, чтобы симуляция была цельной.

## `PlayerAction`

```json
{
  "action_type": "HARVEST_PLANT",
  "payload": { "tile_id": "p1_t3" }
}
```

## Правила

1. Клетка существует, `owner_player_id == player_id`, `occupant_type == "PLANT"`.
2. `growth_elapsed_sec >= growth_time_sec` (иначе `HARVEST_FAILED` `NOT_RIPE`).
3. `water_level >= 50` (иначе `HARVEST_FAILED` `NOT_READY`).
4. Успех: инвентарь `+2` продукта (`plants.product_id` → через payload `product_id` на tile / `occupant_id` = plant_id).
5. Клетка → `EMPTY`, событие `PLANT_HARVESTED` `{tile_id, product_id, amount: 2, player_id}`.

**Важно:** движок **не читает SQLite**. `product_id` урожая = `plant_id` на клетке (как сейчас при посадке).

## Ошибки (`HARVEST_FAILED`)

| reason | Когда |
|--------|--------|
| `UNKNOWN_TILE` | нет клетки |
| `NOT_OWNER` | чужая грядка |
| `NO_PLANT` | пусто |
| `NOT_RIPE` | рост не завершён |
| `NOT_READY` | мало воды |

## Координация с `NIKITA` (после приёмки)

- Убрать `HARVEST_PLANT` из server-only immediate в `match.py`.
- Оставить в очереди тика → `simulate_tick`.
- Клиент **не менять** (уже шлёт `HARVEST_PLANT`).

## Checkpoint 2 — «Harvest Approved»

- [ ] Успешный сбор на созревшей клетке.
- [ ] Все 5 ошибок из таблицы.
- [ ] Stub == C++.

# Фаза 3 — Завод: таймер рецепта в движке (приоритет MEDIUM)

## Смысл

Сейчас после `simulate_tick` сервер в `_advance_factories` уменьшает `remaining_time_sec` и выдаёт продукт.  
Это **не детерминировано в одном месте** с actions. Лучше: **конец тика в движке** обрабатывает все фабрики.

## Поведение (каждый тик, после обработки actions)

Для каждой `factory` с `active_recipe_id != null` и `remaining_time_sec > 0`:

1. `remaining_time_sec -= 1`
2. Если стало `0`:
   - `RECIPE_FINISHED` с `{factory_id, recipe_id, product_id, player_id}`  
     (`product_id` = output рецепта — **передаётся в payload `START_RECIPE`** с сервера: `output_product_id`)
   - Начислить `+1` в инвентарь владельца
   - `active_recipe_id = null`

## Изменение обогащения `START_RECIPE` (делает `NIKITA`)

Сервер добавит в payload перед движком:

```json
{
  "factory_id": "p1_bakery_1",
  "recipe_id": "bread",
  "duration_sec": 30,
  "output_product_id": "bread"
}
```

Ингредиенты по-прежнему списывает сервер **до** вызова движка (`gameplay/004`).

## Checkpoint 3 — «Factory Tick Approved»

- [ ] `START_RECIPE` → через 30 тиков `RECIPE_FINISHED` и bread в инвентаре.
- [ ] Сервер может отключить `_advance_factories` (PR `NIKITA`).
