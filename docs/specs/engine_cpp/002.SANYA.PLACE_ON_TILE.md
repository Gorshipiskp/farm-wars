# Context

Клиент (`NIKITA`) уже отправляет действие `PLACE_ON_TILE` с полями `{tile_id, plant_id}`.
Сервер передает действия в `simulate_tick` без изменений.
Движок (`engine_cpp`) пока не обрабатывает этот action — возвращает `INVALID_TYPE`.

Для рабочего вертикального среза нужна посадка растений через движок.

# Goal

Реализовать обработку `PLACE_ON_TILE` в `simulate_tick` (C++ и Python-stub):
- посадить растение на указанную клетку,
- проверить наличие семян в инвентаре игрока,
- списать 1 единицу из инвентаря,
- выставить начальные параметры растения,
- сгенерировать событие `PLANT_PLACED`.

# Scope

**In scope:**
- `PLACE_ON_TILE` для растений (`occupant_type = "PLANT"`).
- Валидация: клетка существует, принадлежит игроку, пустая, зона `PLANT`.
- Проверка инвентаря: у игрока есть `plant_id` в количестве >= 1.
- Списание 1 единицы из инвентаря.
- Установка параметров клетки: `occupant_type`, `occupant_id`, `health`, `water_level`.
- Генерация `PLANT_PLACED` события.
- Обработка ошибок: клетка не найдена, не пустая, не та зона, нет семян.

**Out of scope:**
- Посадка животных (`occupant_type = "ANIMAL"`) — будет отдельно.
- Проверка, что `plant_id` существует в каталоге (движок не имеет доступа к БД).
- Списание денег за посадку (посадка бесплатна, семена покупаются в магазине — зона клиента).

# Functional Requirements

1. При получении `PLACE_ON_TILE` движок:
   - Находит клетку по `tile_id`.
   - Проверяет `tile.owner_player_id == action.player_id`.
   - Проверяет `tile.occupant_type is None or "EMPTY"`.
   - Проверяет `tile.zone_type == "PLANT"`.
   - Находит игрока в `world_state.players` по `player_id`.
   - Проверяет наличие `plant_id` в инвентаре с `amount >= 1`.
   - Уменьшает `amount` на 1 (если стало 0 — удаляет позицию из инвентаря).
   - Устанавливает на клетке: `occupant_type = "PLANT"`, `occupant_id = plant_id`, `health = initial_health`, `water_level = initial_water_level`.
   - Добавляет в events `PLANT_PLACED` с `{tile_id, plant_id, player_id}`.

2. При ошибках возвращает `CONTRACT_ERROR` с понятным сообщением.

# Non-Functional Requirements

- Детерминированность: одинаковый вход → одинаковый выход.
- Исходный `world_state` не мутируется (глубокая копия).
- Python-stub дает идентичный результат с C++ модулем.

# Data Contracts / API Contracts

### `PLACE_ON_TILE` — payload (обогащенный сервером)

Сервер (зона `NIKITA`) обязан добавить поля `initial_health` и `initial_water_level`
из БД перед вызовом `simulate_tick`. Клиент отправляет только `{tile_id, plant_id}`.

```json
{
  "tile_id": "p1_t1",
  "plant_id": "wheat",
  "initial_health": 100,
  "initial_water_level": 50
}
```

| Поле | Тип | Откуда берется |
|---|---|---|
| `tile_id` | string | Клиент |
| `plant_id` | string | Клиент |
| `initial_health` | number | Сервер (константа 100) |
| `initial_water_level` | number | Сервер (из `plants.initial_water_level` в БД) |

### Событие `PLANT_PLACED`

```json
{
  "contract_version": "v1",
  "event_type": "PLANT_PLACED",
  "server_tick": 5,
  "payload": {
    "tile_id": "p1_t1",
    "plant_id": "wheat",
    "player_id": "p1"
  }
}
```

### Ошибки

| Ситуация | error_code | message |
|---|---|---|
| Клетка не найдена | `MISSING_FIELD` | `Tile not found: {tile_id}` |
| Клетка занята | `INVALID_TYPE` | `Tile already occupied: {tile_id}` |
| Не та зона | `INVALID_TYPE` | `Tile zone is {zone_type}, expected PLANT` |
| Нет семян в инвентаре | `MISSING_FIELD` | `No {plant_id} in inventory for player {player_id}` |
| Клетка не принадлежит игроку | `INVALID_TYPE` | `Tile {tile_id} not owned by {player_id}` |
