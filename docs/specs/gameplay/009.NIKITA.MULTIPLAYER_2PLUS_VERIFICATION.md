# Context

MVP требует стабильного мультиплеера на **2+ игроков**: отдельные фермы, синхронизация гостей после старта хоста, PvP-саботаж, одна победа на матч. Регрессии (залипшее лобби у гостя, чужие действия на чужих клетках, устаревший `shop_handler`) должны ловиться автотестами и ручным сценарием.

# Goal

Зафиксировать проверенное поведение мультиплеера 2–4 игроков, автотесты, ручный E2E и известные ограничения.

# Scope

**In scope:**

- join по коду до `start`; отказ после старта;
- `world_factory`: у каждого `pN` свои `pN_t*` и `pN_bakery_1`;
- гости: poll `/sync` в лобби → вход в матч;
- действия только на своих клетках (движок);
- саботаж по чужим клеткам (`server/008`);
- победа одного, остальные видят `MATCH_FINISHED` в sync;
- автотест `tools/test_multiplayer.py`.

**Out of scope:**

- matchmaking, реконнект с сохранением сессии;
- WebSocket push;
- проверка владельца `START_RECIPE` на чужой пекарне в C++ (см. `server/009` — backlog).

# Functional Requirements

## Матч и игроки

| Правило | Реализация |
|---------|------------|
| Хост = `p1`, гости = `p2`, `p3`, … | `server/registry.py` |
| Join только в статусе `WAITING` | `ValueError MATCH_ALREADY_STARTED` |
| Старт только хостом | `POST /api/matches/start` |
| 2–4 игрока в одном матче | seed + `world_factory` |

## Синхронизация

| Роль | Поведение |
|------|-----------|
| Хост | Create → Start → `session.enable_sync()` + poller |
| Гость | Join → лобби → `_poll_match_started()` (~350 ms) → при `world_state` в sync → `_enter_match()` |
| Все | `GET /api/matches/{id}/sync?since_tick=N` — authoritative state |

## Действия и PvP

- `WATER_PLANT`, `PLACE_ON_TILE`, `HARVEST_PLANT`, `FEED_ANIMAL`: `owner_player_id` должен совпадать с `player_id` (движок → `CONTRACT_ERROR` или `*_FAILED`).
- `APPLY_SABOTAGE`: цель — **чужая** клетка; событие `SABOTAGE_APPLIED` с `target_player_id`.
- `BUY_*`, `SELL_PRODUCT`: server-only, до движка.

## Клиент (MP UX)

- Левый клик — только кнопка 1 (`ui.is_left_click`), не колёсико.
- **Esc** — `_leave_match_to_lobby()`: poller стоп, сброс live state, не возврат в старый матч.
- Версии `shop_handler`: клиент принимает `immediate_v7` … `immediate_v3` (см. `client/main.py`).

# Non-Functional Requirements

- Автотесты MP без pygame-окна.
- Пересборка `engine_core` возможна только когда **не** запущены `py -m server` / `py -m client` (блокировка `.pyd` на Windows).
- Темп матча: **4 тика/сек** (`FARM_WARS_TICK_SEC=0.25`); поля `*_sec` в мире = **тики симуляции** (`shared/game_pacing.py`).

# Data Contracts / API Contracts

Без изменений v1. См. `docs/contracts/GAME_CONTRACTS_V1.md`, раздел `WATER_PLANT` (владелец клетки).

`SHOP_HANDLER_VERSION` на сервере: `immediate_v7` (`server/match.py`); в `/api/health` → `shop_handler`.

## Ручной E2E (2–3 клиента)

1. `py tools/init_db.py --seed`
2. `py -m server` — записать **join code** и **LAN IP**
3. **Хост:** Connect → Создать → **Начать**
4. **Гость 1..N:** IP хоста → Connect → Войти по коду → дождаться «Матч начался» (без залипания в лобби)
5. Каждый поливает **свою** грядку (W) — OK
6. Клик по **чужой** ферме (низ экрана) → саботаж (X / UI)
7. Один игрок печёт `bread` → overlay победы у всех после sync

## Сборка движка (Windows)

| Ситуация | Действие |
|----------|----------|
| `Permission denied` на `.pyd` | Остановить server + client, затем `py tools/build_engine.py` |
| python.org + MinGW g++ | Возможен ABI mismatch; предпочтительно **MSVC** или Python из MSYS2 |
| Без C++ | Сервер использует `engine_core_stub` (owner-check для воды тоже есть) |
